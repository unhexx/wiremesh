# Исходное видение проекта (Project Brief)

> Документ перенесён из исходного описания проекта для сохранения контекста.

## 1. Цели и позиционирование

Создать отдельный проект, предоставляющий функциональность, аналогичную Tailscale/ZeroTier: безопасная виртуальная L3/L4‑сеть поверх существующей инфраструктуры, с mesh‑подключениями между узлами, управляемая через web‑интерфейс.

Сервис должен быть полностью самохостируемым: собственный домен, собственный хостинг, собственный control plane (координационный сервер), без зависимости от внешних SaaS.

Первая целевая платформа для агента — Arch Linux (возможна поставка через AUR / pacman), затем расширение на другие дистрибутивы Linux, macOS, Windows, *BSD.

Установка и подключение агента к серверу должно происходить в один простой шаг (одна команда или один кликабельный инсталлер + автологин).

После подключения: управление таблицей маршрутов, DNS‑настройками и exit‑узлами виртуальной сети через web‑интерфейс.

## 2. Анализ референс‑решений

### 2.1. Tailscale

Tailscale строит mesh‑сеть поверх WireGuard в качестве data plane: каждое устройство получает WireGuard‑ключи и устанавливает зашифрованные туннели напрямую к другим участникам сети.

Control plane реализован через координационный сервер (login.tailscale.com), куда узлы отправляют публичные ключи и актуальные адреса, а оттуда получают список пиров и политики; при этом трафик данных идёт напрямую между узлами (zero trust, end‑to‑end шифрование).

Поддерживаются режимы subnet router и exit node.

**Вывод:** Логично использовать WireGuard как data plane. Нужен собственный координационный сервер.

### 2.2. ZeroTier

ZeroTier реализует собственный wire‑протокол поверх UDP, создавая виртуальную L2/L3 сеть с возможностью самохостинга контроллеров.

**Вывод:** Архитектурно близко. Для MVP опираться на WireGuard, а не разрабатывать свой протокол.

## 3. MCP-интеграция

Реализовать MCP‑сервер поверх control plane:

- Ресурсы: список узлов, маршрутов, DNS‑настроек, статусов соединений.
- Инструменты: добавление/удаление маршрутов, смена DNS, включение/выключение exit‑узлов, создание новых виртуальных сетей.

Это позволит подключать LLM‑агентов как MCP‑клиентов для автоматизации сетевых операций.
